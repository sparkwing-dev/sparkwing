# Migrating to v0.72.0

## Admin session output

`admin session` returns a JSON object when stdout is piped. Enrollment reads
the raw session, so add `--output plain` to enrollment scripts.

Before:

```sh
kubectl exec deployment/sparkwing-controller -- sparkwing-controller admin session \
  --operator ACCOUNT_ID --team TEAM --reason "enroll build box" | \
  sparkwing runners add --session-stdin --profile work --runner build-box --repos 'github.com/acme/*'
```

After:

```sh
kubectl exec deployment/sparkwing-controller -- sparkwing-controller admin session \
  --operator ACCOUNT_ID --team TEAM --reason "enroll build box" --output plain | \
  sparkwing runners add --session-stdin --profile work --runner build-box --repos 'github.com/acme/*'
```

For JSON consumers, read the `session` field. Use `--output json` to keep
that shape when stdout is a terminal. `freeze`, `unfreeze` and `grant` also
select pretty output on a terminal and JSON in pipes; scripts that parse
JSON can pin `--output json`. Plain output returns the team slug for
freeze/unfreeze and the grant ID for grant. Help follows the same output
selection and returns a `kind: help` text record in JSON mode.

## Bound object presence requests

`POST /api/v1/data/has-many` requires a nonzero RFC3339 `deadline` alongside
`digests`. Send the caller's query deadline; a missing deadline returns `400`.
Both Go data clients require an explicit presence budget. The server stops
presence work at the earlier of the caller's deadline and its 30-second response
window. Requests that expire or are cancelled return an error without partial
presence results.

## Dispatch requirement metadata

`pipelines.Pipeline.Requires` is removed. Dispatch metadata describes pipeline identity and triggers. The host resolves execution requirements from project declarations and request overrides. YAML `defaults.requires` and pipeline `requires` keep their syntax and precedence.

Code inspecting raw declarations can use the parsed project:

```go
// Before
requires := cfg.Registry().Find("build").Requires

// After: inspect declarations, preserving unset versus explicit empty.
defaults := cfg.Defaults
pipelines := cfg.Pipelines
```

Do not derive a planning claim from registry membership. SDK pipelines may have no YAML entry.

## Engine compatibility query

`GET /api/v1/capabilities` returns deployment features and no longer accepts
the `engine_version` query parameter. Remove that parameter from callers.

The OpenAPI `components.schemas.internal.controllerwire.Compatibility` response
type is removed, including
its `api_major`, `engine_release`, `guaranteed_until` and `released_at` fields.
Stop reading engine support windows from this endpoint. Engine selection,
signed version enforcement and runner policy keep their existing behavior.

## Independent SDK and engine policy

SDK pins select a signed SDK entry and the newest permitted engine accepting its protocol. SDK and engine versions can differ. Refresh the local signed mapping with `sparkwing update` before running a newly published SDK offline.

`pipeline upgrade --version v0.72.0` selects SDK v0.72.0. It does not request engine v0.72.0. Without `--version`, the command selects the latest permitted SDK for the repository's language. Engine updates still select engine versions.

Plain upgrade output changes from one SDK version line to `sdk=VERSION` and `engine=VERSION` on separate lines. Scripts needing structured output should use `sparkwing pipeline upgrade -o json` and read `after.version` for the SDK and `engine.version` for the engine.

Policy publishers retain SDK entries and each engine's accepted protocol declarations in the signed policy. Publish both `sdk-entry-go.json` and `sdk-entry-typescript.json` on the engine release before publishing its index. See [Signed SDK and engine policy](../engine-policy.md).

## Lean Go SDK module

SDK-only pipeline modules now require `github.com/sparkwing-dev/sparkwing/sparkwing`
instead of the root `github.com/sparkwing-dev/sparkwing` module. Existing SDK
source imports stay unchanged. Pin a published SDK version, then run `go mod tidy`
to regenerate sums. Remove the old root requirement when the pipeline only uses
SDK packages, because old root versions still contain the same import path.

Author tests change their import from
`github.com/sparkwing-dev/sparkwing/sparkwing/sparkwingtest` to
`github.com/sparkwing-dev/sparkwing/sparkwingtest`. These tests still require the
root host module and its Go minimum. Upgrade that host requirement to a version
containing the split before adding the nested SDK requirement.

Source development uses the committed `go.work` file. Root-only `go test ./...`
no longer runs SDK tests. Run `GOWORK=off go -C sparkwing test ./...` as well.
The root manifest has no replacements. A workspace-off build uses the published
SDK pin. Before the first SDK release, checkout verification uses a temporary
modfile replacement rather than changing the publishable root manifest.

The removed `github.com/sparkwing-dev/sparkwing/pkg/match.ToolPrefix` constant
is now `github.com/sparkwing-dev/sparkwing/sparkwing/protocol/labels.ToolPrefix`.
Update the import to the SDK-owned labels package.

Go SDK tags use `sparkwing/v0.x.y`. Engine tags remain `v0.x.y`.

## Upgrade the store in place to schema baseline 37

Schemas 30 through 36 upgrade in place. Schema 37 drops the unused team
build-trust table and preserves secrets, teams, tokens, runner registrations,
GitHub App installations, schedules, subscriptions and Actions records, including
both direct team foreign keys. The `/api/v1/team/build-trust` route, including
its GET and PUT operations, is removed. Remove calls to this endpoint. Execution
trust still follows sealed provenance and host facts. Older binaries refuse the
upgraded store.

## Windows batch arguments

Windows commands that resolve to `.cmd` or `.bat` now run as
`cmd.exe /e:ON /v:OFF /d /c` from the system directory with each argument quoted
and escaped for cmd.exe, following Rust's fix for CVE-2024-24576: an argument is
quoted unless it is nonempty, does not end with `\`, and uses only letters, digits,
non-ASCII text and `#$*+-./:?@\_`, and `%` is written as `%%cd:~,%`. `&`, `|`,
`<`, `>`, `^`, `(`, `)`, `!` and `%VAR%` reach the batch file literally. A `"` is passed
as `""`, which programs using the Microsoft C runtime, such as `node.exe` behind
`npm.cmd`, read back as one quote. Arguments containing CR, LF or NUL are refused,
as are batch file paths containing `"`, `^` or `%`; the error identifies the
`argv` position. Use a non-batch executable, such as `node.exe` with the tool's
JavaScript entrypoint, to pass those values. A batch file that enables delayed
expansion or expands its arguments without quotes reparses them itself.

Executable lookup no longer implicitly searches the Windows working directory.
Install tools on PATH or use an explicit path such as `.\tool.exe`. Empty Windows
PATH entries are skipped. A `.` PATH entry still explicitly selects the working
directory.

## Windows commands run in the host

Windows now runs Go and TypeScript SDK commands in the host, using a Job Object
for cancellation and descendant cleanup. Upgrade the host and SDK pins together.
Commands require a bound host service.

`Run` streams masked output to the job log and retains the last 64 KiB of masked
stdout and stderr. Use `Capture` when parsing complete command output. `String`,
`Lines`, `JSON` and `MustBeEmpty` (and their TypeScript equivalents) already capture.

For Windows Go commands, `ExecError.Cause` no longer wraps `*exec.ExitError`.
Use `errors.As` to read `*sparkwing.ExecError`, then inspect `ExitCode` and
`Terminated`. Deadline causes remain available through `errors.Is`.
