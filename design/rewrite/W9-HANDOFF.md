# W9 continuation handoff

W9 is incomplete. The final grammar parser and shared engine HTTP client are
implemented, but the legacy CLI and client consumers still need migration.
Do not treat the focused acceptance tests as full surface acceptance.

## Implemented

- `clisurface.Parse` reads the final registry, accepts command flags before or
  after verbs, preserves explicit presence, and keeps pipeline arguments behind
  `--`. It validates output, kind selectors, required flags, scalar repetition,
  comma lists, numeric minima, durations, dependencies, conflicts and here-resume
  constraints without side effects. Production CLI dispatch is not wired to it.
- `client.NewEngineClient` implements every `controllerwire.Controller` method.
  Requests use the declared C2 route policy, replay identical bytes, preserve
  idempotency keys, and retry only eligible transient failures or structured
  unavailable/rate-limited responses with Retry-After. Credentials stay in the
  transport. Redirects are refused. Custom HTTP transports support api.sock.
- Response reads accept additive fields and preserve unknown error codes, validate
  required fields recursively, reject duplicate and case-folded field names,
  and unwrap errors once through `apierr.DecodeInner`. The latter remains a W2
  stub, so error tests inject its declared behavior.
- `CompatibilityFor` derives twelve calendar months from the published date.
- `runs bounce`, `debug rerun`, their CLI handlers/tests/help, and the client
  `RequestNodeBounce` method are deleted. Current docs, generated CLI references,
  their embedded mirrors and the changelog reflect those removals. The surviving
  internal bounce polling APIs still have runtime consumers.
- Added a CLI-reference drift test. References were regenerated by calling the
  existing renderer in a temporary test, which was then deleted. No Sparkwing
  executable was run.

## Contract decisions

Local W9 repair: `EngineOptions.Launcher` explicitly selects the launcher claim
route for node-only, plan/eval and named selections. Kinds cannot distinguish a
runner's `nodes.claim` credential from a launcher's `claims.launch` credential.
The server still checks authority. The constructor contract is documented in
`contracts/c3-controller-wire.md`. Launcher callers must set this option.

W2 change needed: there is no route for one ordered queue scan accepting mixed
trigger/job kinds. `ClaimRequest.Kinds` permits this selection, while the route
registry only provides separate runner run/job queues. The client refuses this
combination with `capability_unsupported`; it does not issue two scans that could
change queue order. Agree on a shared claim route and its authorization policy.

`Flag.Required` means explicit presence in the frozen grammar. A destructive
handler must still check an affirmative `Bool("yes")`; parsing `--yes=false`
does not grant confirmation.
